# Prototype 制作計劃：硬體與控制系統


## 0. 範圍界定

**負責**:現成 XY 繪圖機的選定與改造(筆→軟管噴嘴)、G-code 傳送鏈、給水系(蠕動汞)、Max/MSP 總控(狀態機)、水分感測(Arduino)、乾燥(風扇)。
**不負責**:ML 線生成、gcode.ngc 的內容(由生成側藁科さん提供;本計劃只定義交接介面,見 §4)。

## 1. 目標與里程碑

在 1–2 塊混凝土磚的縮小尺度上,**無人介入連續跑完 3 次以上完整循環**:

> 乾燥偵測(≥閾值) → 載入 gcode → 描畫(泵 ON) → 描畫完成+濕潤偵測(≤閾值) → 風扇乾燥 → 回到乾燥偵測

驗證的是循環的成立,以及線的物理品質(水線寬度、濃淡、連續性)。不包含線條內容的生成。

兩段里程碑:

- **9/18(線上會議)**:桌上型全循環 demo(小型套件改造+泵)
- **9/30(定例)**:prototype 正式披露(桌上版全循環+放大改造的進度);放大版(延長框架)於 W9 以降接續

## 2. Prototpye 實作順序：按未知度排序

| 未知度 | 部分                         | 理由                                                           |
| --- | -------------------------- | ------------------------------------------------------------ |
| ★★★ | 1. 繪圖機控制板如何控泵<br>2. 筆→軟管改造 | 推測「G-code M3 M5 → 電動ポンプ」,但現成機的控制板能否輸出訊號控泵？噴嘴改造後的出水行為，都要實物驗證。 |
| ★★☆ | 給水:泵與運動的同步、殘滴、線寬           | 與描畫的部分高度相關。                                                  |
| ★☆☆ | Max 總控制、G-code streaming   | 純軟體，已知領域                                                     |
| ☆☆☆ | 水分感測、繼電器風扇                 | 周邊元件，已知領域                                                    |

**施工順序:二階段制。** 第一階段先改造繪圖機本身——讓它能依照原本的流程讀取 gcode 檔案、控制蠕動泵、畫畫(Part 1–3)。基本邏輯確認無誤後，才進入第二階段的訊號處理與感測(Part 4–6)。

## 3. 模組分解與驗證項目

## 第一階段:基本邏輯——讀檔→控泵→畫畫(Part 1–3)

### Part 1 繪圖機購買

| 項目   | 內容                                                                                                                             |
| ---- | ------------------------------------------------------------------------------------------------------------------------------ |
| 方針   | **買小型套件改造,之後延長放大**。在台灣買 A3 級筆式笛卡爾式繪圖機套件(GRBL 系)。<br>正式尺寸(約1073×1280)不另購機器，而是更換部分元件——**馬達・控制板・滑輪等傳動元件全部從套件移植**只換鋁擠+皮帶+線材        |
| 選定基準 | ①控制板 GRBL 相容 <br>②有抬筆輸出功能(→Part 2 泵開關用) <br>③**構型可延長:V-slot 2020 系鋁擠+笛卡爾式(避開 CoreXY)** <br>④傳動元件為標準品<br>⑤行程 ≥ 磚1塊(190mm×390mm) |
| 驗證   | 1. 出廠狀態畫筆跑 dummy gcode。<br>2. 理解繪圖機軟硬體架構。                                                                                      |
| 檢核   | 用現成 sender 讀取 gcode 檔案，現成機用筆畫出軌跡                                                                                               |

### Part 2 泵控制:控制板→蠕動泵

| 項目   | 內容                                                                                 |
| ---- | ---------------------------------------------------------------------------------- |
| 構成   | **將抬筆訊號作為泵的開關：下筆=出水、抬筆=停水**。                                                       |
| 驗證   | 1. 將該機抬筆訊號轉為控制蠕動汞的開關。<br>2. 時間差測試:下筆訊號後泵轉多久水才到噴嘴(管路長度和延遲之間的關係，可能需要提前給出訊號？)抬筆後殘滴多久? |
| 注意事項 | 控制板邏輯腳位不能直接推動汞，需要額外電供+MOSFET。                                                      |
| 檢核   | part1 的流程變成畫出水畫線、抬筆移動階段不會滴水                                                        |

### Part 3 改造:筆座→軟管噴嘴

| 項目 | 內容 |
| --- | --- |
| 構成 | 拆筆改裝:筆夾固定細管(噴嘴)+ 矽膠管沿線材佈線 + 蠕動泵;在磚上畫水線 |
| 驗證 | 1. 噴嘴固定方式(固定高度,不隨抬筆機構動)與滴下高度 vs 水滴散開。<br>2. 流量與線寬的關係。<br>3. 殘滴對策:抬筆=停水後的虹吸滴漏 → 止逆閥、噴嘴高度、管路走向。<br>4. 描畫速度與給水量匹配(太快=斷線,太慢=積水)。<br>5. 軟管拖曳對小型機運動精度的影響(重量、拉扯)。 |
| 檢核 | 「會滴水的繪圖機」:dummy gcode 在磚上畫出可辨識的水線 |

> **第一階段完了判定**:機器能讀取 gcode 檔案 → 下筆出水、抬筆停水 → 在磚上畫出可辨識的水線。此判定通過後才開始第二階段。
