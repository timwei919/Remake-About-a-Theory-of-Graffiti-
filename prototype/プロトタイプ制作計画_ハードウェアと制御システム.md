# プロトタイプ制作計画:ハードウェアと制御システム


## 0. 担当範囲

**担当**:既製XYプロッターの選定と改造(ペン→チューブノズル)、G-code送信系、給水系(チューブポンプ)、Max/MSPによる総合制御(ステートマシン)、水分センシング(Arduino)、乾燥(扇風機)。
**担当外**:MLによる線の生成、gcode.ngcの中身(生成側の藁科さんが担当。本計画では受け渡しのインターフェースのみを扱う。§5参照)。

## 1. 目標とマイルストーン

コンクリートブロック1〜2個の縮小スケールで、**人手を介さずにフルサイクルを3回以上連続で回す**:

> 乾燥検知(≥閾値)→ gcode読み込み → 描画(ポンプON)→ 描画完了+湿潤検知(≤閾値)→ 送風乾燥 → 乾燥検知へ戻る

検証の対象はサイクルの成立と、線の物理的な質(水線の幅・濃淡・連続性)。線の中身の生成は含まない。

マイルストーンは二段階:

- **9/18(オンラインMTG)**:卓上版フルサイクルのデモ(小型キット改造+ポンプ)
- **9/30(定例)**:プロトタイプの正式披露(卓上版フルサイクル+拡大改造の進捗)。拡大版(フレーム延長)はW9以降に続ける

## 2. 実装順序:未知の大きい順に

| 未知度 | 部分 | 理由 |
| --- | --- | --- |
| ★★★ | 1. プロッター制御基板からのポンプ制御<br>2. ペン→チューブ改造 | 「G-code M3 M5 → 電動ポンプ」と推測しているものの、既製機の基板から本当にポンプを制御できるのか、ノズル改造後の水の挙動はどうか——いずれも実機でなければ確かめられない。 |
| ★★☆ | 給水:ポンプと動作の同期、液だれ、線幅 | 描画部分と密接に関わる。 |
| ★☆☆ | Max総合制御、G-codeストリーミング | ソフトウェアのみ。既知の領域。 |
| ☆☆☆ | 水分センシング、リレー+扇風機 | 周辺要素。既知の領域。 |

**進め方は二段階制。** 第一段階ではプロッター本体の改造に専念し、本来の流れどおりに——gcodeファイルを読み込み、チューブポンプを制御し、描く——ところまで持っていく(Part 1–3)。この基本ロジックが確認できてから、第二段階の信号処理とセンシングに進む(Part 4–6)。

## 3. モジュール分解と検証項目

## 第一段階:基本ロジック——読み込み→ポンプ制御→描画(Part 1–3)

### Part 1 プロッターの購入

| 項目 | 内容 |
| --- | --- |
| 方針 | **小型キットを買って改造し、のちに延長して拡大する**。台湾でA3級・ペン式・カーテシアン構成のプロッターキット(GRBL系)を購入。本番サイズ(約1073×1280)では買い直さず、部材の一部だけ交換する——**モーター・制御基板・プーリーなど駆動系はキットから移植**し、アルミフレーム+ベルト+配線のみ新調 |
| 選定基準 | ①GRBL互換の制御基板<br>②ペンアップ/ダウン出力があること(→Part 2でポンプのスイッチに転用)<br>③**延長できる構成:V-slot 2020系フレーム+カーテシアン式(CoreXYは避ける)**<br>④駆動系部品が標準品であること<br>⑤ストローク ≥ ブロック1個(190mm×390mm) |
| 検証 | 1. 出荷状態のまま、ペンでdummy gcodeを描かせる。<br>2. プロッターのソフト・ハード構成を把握する。 |
| チェック | 既存のsenderでgcodeファイルを読み込み、ペンで軌跡が描けること |

### Part 2 ポンプ制御:制御基板→チューブポンプ

| 項目 | 内容 |
| --- | --- |
| 構成 | **ペンアップ/ダウン信号をポンプのスイッチに転用する:ペンダウン=給水、ペンアップ=停止**。 |
| 検証 | 1. ペンアップ/ダウン信号をチューブポンプのON/OFFへ変換する。<br>2. 時間差の計測:ペンダウン信号からノズルに水が届くまでの遅れ(チューブ長との関係。信号を先行させる必要があるか?)、ペンアップ後の液だれの持続時間。 |
| 注意 | 制御基板のロジックピンでポンプを直接駆動することはできない。別系統の電源+MOSFETを介す。 |
| チェック | Part 1の流れが「水で線を描く」に変わり、ペンアップの移動区間では水が落ちないこと |

### Part 3 改造:ペンホルダー→チューブノズル

| 項目 | 内容 |
| --- | --- |
| 構成 | ペンを外して細管(ノズル)をクランプに固定+シリコンチューブをケーブルに沿わせて取り回し+チューブポンプ。ブロックの上に水の線を描く。 |
| 検証 | 1. ノズルの固定方法(高さ固定、リフト機構には追従させない)と、滴下高さvs水滴の広がり。<br>2. 流量と線幅の関係。<br>3. 液だれ対策:停止後のサイフォン滴下 → 逆止弁・ノズル高さ・チューブの取り回し。<br>4. 描画速度と給水量のマッチング(速すぎると線が途切れ、遅すぎると水たまりになる)。<br>5. チューブの引きずりが小型機の動作精度に与える影響(重さ・引っ張り)。 |
| チェック | 「水を滴らすプロッター」:dummy gcodeで、ブロックに識別できる水線が描けること |

> **第一段階の完了判定**:gcodeファイルを読み込める → ペンダウンで給水・ペンアップで停止 → ブロックに識別できる水線が描ける。ここを通過してから第二段階に入る。
