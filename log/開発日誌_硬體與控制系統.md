## 8/23 拆控制盒,找訊號

- 找到雷射的控制訊號(白線),泵可以直接接主控板

把控制盒打開看裡面怎麼接的。

```
綠板(smartDIYs 主控、STM32)
  ├ 紅/黑:12V 電源 → 藍板
  └ 藍/白:控制訊號 → 藍板(雷射定電流驅動)
                        └ LD+/LD− → 雷射頭
```

![](media/20260823_回路解析/20260823_制御ボックス内部_1.png)
![](media/20260823_回路解析/20260823_制御ボックス内部_2.png)

藍板的特寫,還有主控板上的 LASER 接頭:

![](media/20260823_回路解析/20260823_青基板クローズアップ.png)
![](media/20260823_回路解析/20260823_LASERコネクタ.png)

用三用電表量:

| 量測點 | 結果 |
| --- | --- |
| 雷射頭輸出端 LD+/LD− | 照射時 5.8V,停止後慢慢降下來 |
| 白線(對 GND) | 0.2〜0.9V 之間跳動 |
| 藍線(對 GND) | 一直 0V |

一開始想直接拿雷射頭的輸出端當泵的開關訊號,但停止後電壓是慢慢降的(驅動板的電容在放電),不能用。所以開始從電路板中往上游找，才發現綠板和藍板之間的藍白線才是真正的控制訊號。

白線 0.2〜0.9V 這個怪數字,後來想是 PWM,電表只顯示平均值,而且當時雷射出力沒開滿。

**結論:白線是控制訊號。藍板可以整塊跳過,泵直接接主控板的 LASER 接頭。**

## 8/27 蠕動泵單體測試

- 泵單體測試通過,且泵自帶止逆

12V 直接給電,水順利送到管子另一端。切電就停,管子裡不會繼續滴。

蠕動泵的軟管是內徑3mm，外徑5mm。拆除連接器的時候，會因為拔除的拉扯，造成輕微的軟管耗損，未來安裝時需要注意。

## 8/28〜29 Arduino 控制泵 → 雷射訊號直接控泵

- 雷射訊號直接驅動泵成功

準備進行現有機器挪用訊號的工作，進到機器連接之前，先進行Arduino Mega + MOSFET 光耦隔離板控制泵的測試。

先用 Arduino Mega + MOSFET 光耦隔離板(GYJ)控泵,序列埠打指令可以開關。板子有光耦隔離,Arduino 和 12V 不用共地。確認可以運作。

接著把綠板 LASER 接頭的白線藍線**直接**接上 MOSFET 板的訊號輸入,跑 gcode——**雷射該輸出的區間,泵真的轉了。** Arduino 都不需要當中間人。

出力 100% 泵轉得穩，不到30%時水量會幾乎不出水。出力低就會抖。所以 PWM 確實有傳到泵,只是佔空比低的時候扭力不夠。

3. 高解析度照片 → **就是異徑接頭。** 之前以為的溝紋領是寶塔接頭的環狀凸緣,圓錐是它細端本身

*(原作的記錄影像截圖。著作權屬作家與攝影者,不收錄於本 repo)*

從照片看到的另外兩件事:

- **噴嘴尖端幾乎貼著磚面。** 水不是滴下去的,比較像接觸轉移過去。這樣位置才準、也不會濺開。所以噴嘴要盡量壓低,但磚面不平,固定機構得能微調高度。
- **水線很寬,而且沿著混凝土的紋理擴散、積在凹處。** 線寬主要不是噴嘴口徑決定的,是水量和磚的吸水性。要調線寬應該先調泵速和描畫速度。

### 想一下循環時間的問題

如果目標是10~15分鐘跑完一次循環,現在最大的問題是乾燥,不是描畫。

描畫其實很快。速度 4000 跑 3m 的路徑不到3分鐘。但水要乾掉的時間遠比這個長,所以十分鐘裡幾乎全部都花在等乾。也就是說決定循環長度的是泵送水的速度跟水蒸發的速度的比值。

沒有風扇的話這個數字差太多了(9/13 那次 30 分鐘沒乾就是證據)。**風扇不是周邊零件,是循環能不能成立的關鍵。** 原本排在 Part 5,應該提前進行測試，觀察對於蒸發的效率差異。

另外一個還沒用到的變數是**路徑長度**。總水量 = 路徑長 ×(流量/速度),我一直在調流量和速度,但圖樣越疏水量就越少。目前已經很需要藁科さん那邊的機器學習成果，才能更確實的測試水量與蒸發關係。

## 9/15

- 自動化方針定案:滑鼠操作 + 雷射訊號判定結束
- 看懂噴嘴構成:軟管穿在壓克力硬管裡

### 自動化的設計方向

開始想 Max/MSP 的自動化。要做的有三塊:

1. Max 讀 Arduino 的濕度值,到條件就啟動描畫
2. Max 經 Arduino 控固態繼電器開關電風扇(描畫時關、畫完開)
3. 用滑鼠軌跡紀錄去操作 SmartDIYs Creator:點「アイテムを追加」→ 選檔案 → 點 START
4. Max 讀 Arduino 擷取雷射訊號(白線)，一定時間沒出水後，作為繪製結束的判定。


滑鼠自動化看起來像是繞路,但它符合 yang02 的風格——**技術可視化**。議題A 4-3 整理過他「讓人直接看見配線與 patch 畫面」的傾向,OIST 那次他自述講究的是「注意深く追ってくと何がどうなってんのかわかる配線」。

那麼螢幕上游標自己移動、自己點按鈕,這件事本身就是機制的暴露。觀眾看得到機器在操作另一台機器。這不是隱藏起來的自動化,是演出來的自動化。

→ 所以自動化的方式要照原作走,而且**游標的移動應該被看見**。這會影響工具的選擇(見下)。

#### 游標該怎麼動

一開始想的是錄下自己操作的軌跡再重播(人的手勢被錄一次、由機器永遠重複,概念上很對)。但**再看記錄影片,游標的移動非常直線,不像錄下來的人類軌跡**,而是在兩點之間線性插值的程式動作。

那麼原作大概是在 Max 裡直接控游標。最可能的是 **aka.mouse**。原作也是用這個Object。

**但 aka.mouse 已經停止支援**,現在的 Max / macOS 跑不動。所以改用 **11clicks**。
![](media/20260916_ソフトとノズル/11clicks_help.png)
11clicks 預設是瞬移,所以要自己做插值——把路徑切成幾十段,逐段 `m:x,y` + `w:ms`。這樣出來的移動是直線平滑的,跟原作影片看到的一樣。移動時間設 900ms 左右,看起來就像有人在操作。

#### 描畫結束怎麼判定

 **讓 Arduino 也讀雷射訊號(白線)** → 訊號連續靜默 N 秒 = 畫完

選第三個。白線本來就有,只是多接一支腳位。這樣一顆 Arduino 同時做:讀濕度、讀雷射訊號、控風扇。泵還是由雷射訊號直接驅動,不經過 Arduino。

訊號狀態整理:

```
1. 濕度 ≥ 乾燥閾值 + 並非描繪中 → 乾燥待ち(風扇 ON)  
2. 濕度 < 乾燥閾值 + 並非描繪中 → 重播滑鼠軌跡 + 風扇 OFF
3. （描畫中）雷射訊號靜默 N 秒 → 結束
4. 回 1
```

閾值要有遲滯帶，不然讀值在邊界抖動風扇會瘋狂開關。

### 看懂噴嘴那段是怎麼配置的了

終於看懂最終出水那段。**透明的壓克力硬管裡面,看得到軟管稍微蜿蜒的樣子。**

*(原作的記錄影像截圖。著作權屬作家與攝影者,不收錄於本 repo)*
*(原作的記錄影像截圖。著作權屬作家與攝影者,不收錄於本 repo)*

所以構造是:

```
矽膠軟管(推測 內徑3×外徑5)
   ↓ 穿過
透明壓克力硬管(當垂直的固定支撐)
   ↓ 下端露出一小段
矽膠軟管 + 異徑接頭(噴嘴)
```

這解決了 9/9 留下的疑問。之前不確定上面那段是軟管還是硬管,答案是**兩者都是**:軟管在裡面所以看起來半透明,壓克力在外面所以筆直。

### 寫了 Arduino 和 Max/MSP 的程式

#### Arduino:`arduino/GraffitiIO/GraffitiIO.ino`

負責感測與風扇,不管泵(泵由雷射訊號經 MOSFET 板直接驅動)。

做三件事:讀水分感測器、監看雷射訊號算出靜默時間、依指令開關 SSR 控制風扇。每 100ms 送一行 `st <hum> <laser> <silent> <fan>` 給 Max,接收的指令只有 `f1` / `f0`。

接線:A0 水分感測器 / D4 感測器 VCC(只在讀取時通電) / D2 雷射訊號(白線) / D8 SSR。

閾值判斷和狀態機不放在這裡,留給 Max,這樣調閾值不用重燒板子。

#### Max/MSP:`max/GraffitiControl.maxpat`

總指揮。分成六塊:

- **⓪ 狀態欄** 模式、狀態、濕度、出水、靜默秒數、風扇、受信
- **① 通信** 收 Arduino 的序列埠資料並拆成四個值
- **② 判定** 乾燥閾值與靜默閾值,都可即時改
- **③ 狀態遷移** 等乾 ⇄ 描畫中。含 GUARD(描畫剛開始不理靜默判定)與自動/手動模式開關
- **④ 風扇** 送 `f1` / `f0` 給 Arduino
- **⑤ 滑鼠操作** 六步的表:移動 → 左鍵點擊 → 等待,操作瀏覽器版的控制軟體
- **⑥ 手動操作** 繞過自動判斷的按鈕

刻意用純 Max 物件寫,沒有包進 `[js]`——這個 patch 會顯示給觀眾看,黑箱化會抵銷技術可視化那層。

#### Arduino ↔ Max 的實機測試

- Max 讀 Arduino 的濕度值:**成功**
- Max 經 Arduino 控制固態繼電器:**成功**
- 讀雷射訊號:**還沒測**。Type-A 的接口不夠用了(繪圖機、Arduino 都要佔一個),明天帶排數多一點的 Type-C to A 轉接器再接。

| --------------------- | -------------------- | ------------------ |

目前 prototype 用的是第一次展出的薄型(390×190×100)。

#### 為什麼第二次換厚的?(假說)

水在磚上不只是蒸發,也會往磚裡吸。厚的磚吸水容量大,所以連續運轉時要更久才會飽和。

如果這個假說對,那對我來說是個重要的提醒:**乾燥時間可能會隨著運轉時數變長。** 我目前測的都是乾磚的第一次或第二次,單次的數據。要驗證的話,連續跑幾小時看乾燥時間有沒有變長就知道。

#### 要決定的

正式版用哪一種。現在傾向厚型(對應長時間運轉),但要先確認會場的承重和搬入條件。如果只能用薄型,那就把「連續運轉時乾燥時間變長」當成已知的限制來設計循環。
